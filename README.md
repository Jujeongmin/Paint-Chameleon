# Paint Chameleon

몸을 직접 칠하고 자세를 굳혀 술래를 속이는 3D 멀티플레이어 숨바꼭질.
[Verse8 / Agent8](https://docs.verse8.io/ko/docs) 플랫폼용.

> **저작권 안내**
> 이 프로젝트는 "위장하고 숨는 술래잡기"라는 **장르·규칙**을 독자적으로 구현한 것입니다.
> 게임 규칙과 메커니즘은 저작권 보호 대상이 아니지만, 코드·에셋·캐릭터 디자인·이름은 보호 대상입니다.
> 이 저장소의 코드와 배치는 전부 새로 작성했으며, 다른 게임에서 추출한 리소스는 **하나도 포함되어 있지 않습니다.**
> 아레나의 3D 모델(Kenney 에셋 킷)과 텍스처(ambientCG)는 전부 **CC0**(퍼블릭 도메인 수준
> 라이선스, 출처 표기 불필요)로, 상세는 [`public/README.md`](public/README.md)에 있습니다.

## 실행

```bash
npm install && npm run dev
```

`VITE_AGENT8_VERSE`가 없으면 **오프라인 모드**로 뜹니다 — 서버 없이 혼자 로비와 아레나를
돌아보며 전체 루프를 돌려볼 수 있습니다. 페이즈 머신과 점수 계산은 실서버와 같은 규칙을
사용합니다. (`game/src/net/offline.ts`, 프로덕션 빌드에는 영향 없음)

**봇은 없습니다.** AI는 술래가 될 수 없다는 규칙을, 오프라인 리허설에 있던 봇 2명을
아예 없애는 것으로 지킵니다 — 혼자면 항상 술래이므로 규칙이 저절로 지켜집니다. 대가로
오프라인에서는 숨는 쪽을 연습할 수 없습니다.

개발 모드에선 `window.__pcDebug`에 페이즈·타이머·내 위치 상태가 실려 있습니다.

> 기준이라 정상 진행되지만, 관찰할 땐 탭을 앞에 두세요.

## 게임 규칙

| 페이즈 | 시간 | 내용 |
|---|---|---|
| 대기 | — | 2명 이상 전원 준비 시 시작 |
| 숨는 시간 | 30초 | 술래는 지하 밀봉 방(대기실)에서 대기 — 카운트다운·남은 인원 표시, 붓질 연습 가능. 나머지는 자리 잡고 몸을 칠한 뒤 자세 고정 |
| 추적 | 90초 | 술래가 사냥. **페인트 잠김** |
| 결과 | 10초 | 점수 정산 후 다음 라운드 |

**점수** — 생존 100점 / 발각 시 생존한 초당 1점 / 술래는 1명당 75점.
위장 품질은 채점하지 않습니다. 술래가 못 찾으면 이기는 것, 그게 전부입니다.

**조작** — `WASD` 이동, `Shift` 달리기, `Q` 자세, `F` 페인트 모드, 마우스 시점, 클릭으로 사격(술래).
페인트 모드에서는 몸을 드래그해 칠하고, 빈 공간을 드래그해 시점을 돌리고, 휠로 확대합니다.

## 아키텍처에서 중요한 결정들

### 1. 10Hz 상태 동기화로 충분한 이유

Agent8의 `$roomTick`은 **200~1000ms(1~5Hz)** 로 돕니다. 보통 3D 멀티플레이어엔 부족한
레이트지만 이 장르는 예외입니다 — 숨는 쪽은 대부분 정지 상태이고, 투사체가 없어 명중은
클라이언트의 레이캐스트 한 번으로 즉시 결정됩니다. 서버는 명중 여부를 판정하지 않고
시야각 + 쿨다운만 검증하면 충분합니다.

포지션은 `remoteFunction(..., { throttle: 100 })`으로 흘려보내고 클라에서 보간합니다.
**일반 remoteFunction은 초당 ~10회 제한**이 있지만 throttled 호출은 이 제한을 우회합니다.
추가로 `NET_EPSILON` 이하로 움직이면 아예 전송하지 않아서, 가만히 있는 플레이어는 대역폭을 쓰지 않습니다.

### 2. 라운드 타이머는 월클럭

틱 간격이 변동하므로 델타를 누적하면 드리프트가 납니다. `phaseEndsAt`(서버 ms 절대시각)을
기준으로 하고, 매 틱 `tickAt`을 실어 보내 클라이언트가 시계 오프셋을 보정합니다.

### 3. 사격은 틱이 아니라 remote function

틱에서 판정하면 최대 1초가 밀립니다. `requestShot`은 즉시 실행되고, 페이즈·역할·대상(미포획
하이더인지)·쿨다운·시야각을 **서버가 전부 검증**합니다. 명중 자체(벽에 막혔는지)는 서버
검증 대상이 아닙니다 — 서버가 맵을 갖고 있지 않아 벽을 볼 수 없고, 볼 수 있는 건 맵을 든
클라이언트뿐이기 때문입니다. 사거리 제한도 없습니다: 이전에 `TAG.maxDistance` 2.6u가
조작된 클라이언트가 주장할 수 있는 범위의 상한이었는데, 이제 그 상한이 사라졌다는 뜻입니다.
자세한 내용과 그 대가는 아래 "알려진 한계"를 보세요.

### 4. 페인팅: 플레이어 1명당 텍스처 1장

몸통 6개 파츠(머리/몸통/양팔/양다리)를 **하나의 512×512 텍스처에 3×2 격자로 UV 패킹**합니다.
플레이어 한 명이 텍스처 1장 + 머티리얼 1개라, 8명이어도 텍스처 8장입니다.
파츠마다 텍스처를 두면 48장이 됩니다.

붓질은 레이캐스트 히트 → UV → Canvas2D 방사형 그라디언트. 브러시가 붓 폭의 일정 비율 이상
움직였을 때만 점을 기록하고(데시메이션), 받는 쪽에서 점 사이를 보간해 이어붙입니다.

**월드는 칠할 수 없고 자기 몸만 칠합니다.** 그래서 페인트는 순수 시각 요소이고,
서버는 스트로크를 **해석하지 않고 중계만** 합니다 — isolated-vm에서 canvas를 돌릴 수 없는
제약을 우회하는 게 아니라, 아예 서버가 알 필요가 없어집니다.

### 5. 아레나: 손설계 + 에셋 모델, 서버와는 스폰 지점만 공유

아레나는 더 이상 절차적으로 생성되지 않습니다(옛 방식: 색 클러스터 안에 상자를 시드
난수로 흩뿌림). 지금은 구역 4개(드럼통·팔레트·화물상자·선반기둥)에 무리를 손으로
배치하고, 무리마다 플레이어 한 명이 들어갈 빈 슬롯을 의도적으로 남겨 "설계된
은신처"를 만듭니다(`game/src/game/arena.ts`). 겉모습은 Kenney 에셋 킷의 GLB 모델이 맡고,
그 위에 시드 난수로 소품(clutter)을 흩뿌려 규칙성을 깨면서도 라운드마다 똑같은
배치를 보장합니다. 크기는 44×44로 시작해 이번 세션에 **88×88**로 4배 넓어졌습니다
(`ARENA.size`).

서버는 이 지오메트리를 전혀 갖지 않습니다. 서버가 맵을 필요로 했던 유일한 이유가
"하이더를 빈자리에 스폰시키기"였는데, 지금은 손으로 고른 `SPAWN_POINTS`(하이더)와
`CELL_SPAWN`(술래가 숨기 페이즈 동안 대기하는 지하 밀봉 방의 스폰 좌표, 아래 참고)
목록만 압니다. `scripts/check-sync.ts`가 두 목록이 클라이언트·서버 양쪽에서 정확히
같은지 대조합니다. **맵이나 대기실을 수정하면 반드시 돌리세요.**

## 알려진 한계 / 다음 단계

1. **허브(로비)는 구현되어 있습니다** — 걸어다니는 3D 허브, 아바타 상점(마네킹 4개가
   각자 발판을 가진 3D 구조물), 리더보드 기념비(카펫 건너 상점과 대칭 위치, 판면에 순위를
   캔버스 텍스처로 그림), 포털을 통한
   매치 입장이 이미 동작합니다. (이 항목은 한동안 "허브 미구현"으로 적혀 있었는데, 그
   문구 자체가 이미 사실과 달랐던 것을 이번에 바로잡았습니다. 남은 다음 단계는 접속자
   실시간 표시와 포털 자동매칭입니다.)
2. **수평(XZ) 이동만 서버에서 검증됩니다** — `updateTransform`이 직전 위치·경과시간
   기준 최대 이동거리로 XZ를 clamp합니다(`server/src/server.ts`). 순간이동/스피드핵은
   막히지만, Y축(수직)은 아직 검증하지 않습니다 — 점프/낙하가 중력가속도라 수평보다
   순간 속도가 커서, 정상 낙하까지 오탐하지 않는 별도 설계가 필요해 다음 단계로
   남겨뒀습니다.
3. **페인트 중간 참여 미지원** — 라운드는 대기 상태에서만 입장 가능하므로 현재는 문제가 없지만,
   중간 참여를 허용하려면 스트로크 히스토리를 룸 컬렉션에 쌓아 재생해야 합니다.
4. `$roomTick` 실제 주기 미측정 — 배포 후 실측해서 `NET_THROTTLE_MS` 조정 필요
5. 모바일 미지원 / VXShop·Ads 미연동
6. **포인터 락 — 로컬 브라우저에서는 동작 확인됨.** (예전 이 항목은 "이 환경에서 거부됨"
   이었는데, 사실이 아니었습니다. 참가 직후 자동으로 걸리고, Esc로 풀고 클릭으로 다시
   잡는 것까지 수동 테스트로 확인했습니다. 다만 `allow="pointer-lock"` 없는 iframe에
   임베드되면 여전히 거부되고, Verse8 임베드가 그 경우인지는 배포 후 확인이 필요합니다.)

   락은 `HubPlayer`/`LocalPlayer` 마운트 직후(참가 클릭 직후라 문서에 activation이 남아
   있음)와 캔버스 클릭 때마다 시도합니다(`game/src/game/input.ts`의 `usePointerLook`).
   **거부를 절대 캐시하지 않는 것이 핵심입니다.** Chrome은 사용자가 Esc로 락을 빠져나온
   직후 잠깐 재획득을 막는데, 그 일시적 거부를 "이 브라우저는 락을 못 한다"로 저장하면
   이후 모든 클릭이 막혀 **Esc 한 번에 마우스를 영영 다시 못 잡습니다.** 실제로 그 버그가
   있었습니다. 락이 거부되면 자유 시점(버튼 없이 마우스 이동만으로 회전)으로 동작합니다.

   **커서는 락을 실제로 쥐고 있을 때만 숨깁니다.** 자유 시점에서는 진짜 커서가 살아 있고
   캔버스를 벗어나면 `if (e.target !== canvas) return` 때문에 시점 회전이 조용히
   멈추는데, 그 커서를 숨기면 플레이어는 자기 마우스룩을 무력화한 커서가 어디 있는지
   알 수 없게 됩니다. 락 상태에서는 브라우저가 알아서 숨기므로 이 클래스는 보조 수단입니다.

   상점은 이 폴백에 의존하지 않습니다 — 발판에 서서 <kbd>E</kbd> 한 번이면 끝이라 커서도
   클릭도 필요 없습니다. 클릭이 필요한 UI는 페인트 도구와 자세 메뉴뿐입니다.
7. **리더보드 콜렉션의 실제 배포 환경 영속성 미확인** — `$global` 콜렉션(`"leaderboard"`)에
   누적 점수를 쌓지만, 로컬/테스트 구현(`LocalCollectionManager`)은 인메모리라 서버
   프로세스가 재시작되면 사라집니다. 실제 Verse8 인프라가 이 콜렉션을 재시작 너머로
   영속시키는지는 배포 후 확인 필요.
8. **아바타 상점: 라운드 종료 시 코인 적립이 자동 검증되지 않습니다** — 리더보드와 같은
   벽입니다. `@agent8/gameserver-node` 테스트 하네스가 라운드를 끝까지(결과 페이즈까지)
   진행시키지 못해서, 실제 라운드 종료 때 `wallets` 콜렉션에 코인이 더해지는 경로는
   서버를 띄운 통합 테스트로 재현할 수 없습니다. `coinsFor`의 순수 계산 로직 자체는
   `npm run check:shop`이 커버하지만, `endRound`가 그 값을 실제로 적립하는 배선은 코드
   리뷰로만 확인했습니다. 같은 이유로 "구매" 자체도 살아있는 서버에서 재현 불가능합니다
   — 테스트가 스스로 코인을 지급할 원격 메서드가 없기 때문인데(누구나 자기 잔액을
   마음대로 설정할 수 있게 되므로 의도적으로 만들지 않았습니다), 그래서 구매 성공 경로도
   순수 로직 검증 + 코드 리뷰로만 확인된 상태입니다.
9. **`wallets` 콜렉션의 실제 배포 환경 영속성 미확인** — 리더보드 콜렉션(7번)과 정확히
   같은 사정입니다. 로컬 구현이 인메모리라 서버 재시작을 넘어서는지는 배포 후 확인이
   필요합니다.
10. **아바타 체형은 키·발높이·최대 반폭만 동일하고, 실루엣 면적·깊이는 균일화되지
    않습니다** — 네 가지 체형(`classic`/`bean`/`stick`/`tank`) 전부 총 키(1.86)·발
    높이(0.13)·**로컬 X축 기준** 최대 반폭(`maxHalfWidth` ≤ `MOVE.playerRadius` 0.45)이
    동일하고, 충돌 반지름·카메라도 아바타와 무관한 전역 상수입니다 — 사격은 이제 사거리
    제한 자체가 없어 이 얘기가 무의미해졌지만(13번 참고), 그렇다고 체형이 사격에서
    유리해지지도 않습니다. 그래서 어떤 아바타도 다른 아바타가 물리적으로 닿지 못하는
    은신처에 도달할 수 없고, 위장의 핵심 메커니즘인 페인팅도 영향받지 않습니다. 하지만 이 불변식은
    로컬 X축 폭만 잡을 뿐, **정면 실루엣 면적과 깊이(Z축)는 균일화하지 않습니다**:

    | 체형 | 가격 | 정면 실루엣 면적 | classic 대비 | 최대 깊이(반폭) |
    |---|---|---|---|---|
    | `stick` | 60 | 0.90 | −26% | 0.26 |
    | `classic` | 0 | 1.21 | — | 0.34 |
    | `tank` | 90 | 1.41 | +16% | 0.30 |
    | `bean` | 40 | 1.46 | +21% | 0.40 |

    몸이 플레이어와 함께 회전하므로 요(yaw) 90도에서는 이 깊이가 실질 폭이 되는데,
    거기서는 `stick`이 `bean`보다 35% 좁습니다. 2차적인 차이이긴 합니다 — 충돌 반지름이
    모든 체형에 균일한 0.45라 이동/도달 범위에는 영향이 없고 — 이지만 실재하는 차이이므로
    "순수 외형"이라고 뭉뚱그리지 않고 정확히 무엇이 보장되는지를 여기 적어둡니다. 높이·
    발 높이는 프로필에서 아예 저장하지 않고 파생시켜(derive) 위반 자체를 표현할 수 없게
    했고, 로컬 X축 폭과 피벗 위치는 `validateProfile()`이 검사하며 `npm run check:bodies`가
    전체 카탈로그에 대해 이를 돌립니다.
11. **밸런스 미검증** — 숨기 30초 / 술래 90초는 옛 44×44 아레나 기준으로 튜닝된 값입니다.
    아레나가 이번 세션에 88×88로 4배 넓어져 대각선이 124u가 됐고, 하이더 속도(6u/s)로
    가로지르는 데 약 21초가 걸립니다. 숨기 시간이 넓어진 맵에 비해 부족한지, 술래
    90초가 4배 넓은 맵을 수색하기에 넉넉한지 실제로 플레이해봐야 압니다.
12. **성능 미측정** — 아레나 하나에 콜리전 박스(=대부분 모델) 621개가 있습니다
    (`game/src/game/arena.ts`의 `MAP_BOXES`). 인스턴싱은 아직 없어서 같은 모델(드럼통·
    화물상자 등)이 반복될 때마다 별도 드로우콜이 나갑니다. 저사양 기기에서 프레임이
    떨어지는지 확인이 필요합니다.
13. **사격 요청의 상한이 없어졌습니다.** 이전에는 `TAG.maxDistance` 2.6u가 조작된
    클라이언트가 주장할 수 있는 범위의 상한이었습니다. 명중 판정은 클라이언트로 넘어갔습니다
    — 벽 판정을 하려면 맵이 있어야 하는데, 맵을 든 쪽이 클라이언트뿐이기 때문입니다(서버
    사본은 7차 세션에 지웠습니다 — 위 5번 참고). 그래서 서버에 남은 검사는 페이즈·역할·
    대상(미포획 하이더인지)·쿨다운·시야각뿐이고, 거리와 시야는 검사하지 않습니다 — **맵
    어디의 누구든 이름만 알면 잡았다고 주장할 수 있습니다.** 서버가 맵을 다시 갖지 않는 한
    되찾을 수 없는 구멍입니다. 벽을 못 보는 서버가 지금 고르는 어떤 거리 상한도 근거 없는
    임의값이기 때문입니다.
14. **사격 밸런스 미검증** — 무제한 사거리 + 한 발에 잡히는 판정이 하이더에게 얼마나
    불리한지 아직 아무도 모릅니다. 완화책은 이미 맵에 있습니다(풍차 칸막이, 88×88 아레나에
    흩뿌린 소품 440개). 손잡이가 될 수 있는 값은 사거리 상한·쿨다운(`SHOT.cooldownMs`)·한 발/여러
    발 여부입니다.

## 튜닝

밸런스 상수는 [`game/src/game/constants.ts`](game/src/game/constants.ts)에 모여 있습니다
(서버 사본은 `server/src/rules.ts`). 바꿔볼 만한 것:

- `PHASE_SECONDS.hiding` — 30초가 칠하기에 충분한지 (88×88 아레나 기준으로는 미검증)
- `SHOT.minFacingDot` / `cooldownMs` — 사격이 너무 관대한지 빡빡한지 (사거리 상한은 없습니다 — 13번 참고)
- `BRUSH.default` / `PAINT_FLUSH_MS` — 붓 감각과 동기화 지연
- `Humanoid.tsx`의 `POSE_TARGETS` — 자세별 실루엣
