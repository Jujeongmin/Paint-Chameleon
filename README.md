# Paint Chameleon

몸을 직접 칠하고 자세를 굳혀 술래를 속이는 3D 멀티플레이어 숨바꼭질.
[Verse8 / Agent8](https://docs.verse8.io/ko/docs) 플랫폼용.

> **저작권 안내**
> 이 프로젝트는 "위장하고 숨는 술래잡기"라는 **장르·규칙**을 독자적으로 구현한 것입니다.
> 게임 규칙과 메커니즘은 저작권 보호 대상이 아니지만, 코드·에셋·캐릭터 디자인·이름은 보호 대상입니다.
> 이 저장소의 코드와 에셋은 전부 새로 작성했으며, 다른 게임에서 추출한 리소스는 **하나도 포함되어 있지 않습니다.**
> 3D 지오메트리는 전부 코드로 절차 생성되므로 외부 에셋 라이선스 문제가 없습니다.

## 게임 규칙

| 페이즈 | 시간 | 내용 |
|---|---|---|
| 대기 | — | 2명 이상 전원 준비 시 시작 |
| 숨는 시간 | 45초 | 술래는 눈을 감음. 나머지는 자리 잡고 몸을 칠한 뒤 자세 고정 |
| 추적 | 90초 | 술래가 사냥. **페인트 잠김** |
| 결과 | 10초 | 점수 정산 후 다음 라운드 |

**점수** — 생존 100점 / 발각 시 생존한 초당 1점 / 술래는 1명당 75점.
위장 품질은 채점하지 않습니다. 술래가 못 찾으면 이기는 것, 그게 전부입니다.

**조작** — `WASD` 이동, `Shift` 달리기, `Q` 자세, `F` 페인트 모드, 마우스 시점, 클릭으로 태그(술래).
페인트 모드에서는 몸을 드래그해 칠하고, 빈 공간을 드래그해 시점을 돌리고, 휠로 확대합니다.

## 아키텍처에서 중요한 결정들

### 1. 10Hz 상태 동기화로 충분한 이유

Agent8의 `$roomTick`은 **200~1000ms(1~5Hz)** 로 돕니다. 보통 3D 멀티플레이어엔 부족한
레이트지만 이 장르는 예외입니다 — 숨는 쪽은 대부분 정지 상태이고, 투사체나 정밀 히트박스가
없어 태그는 거리 + 시야각 판정으로 충분합니다.

포지션은 `remoteFunction(..., { throttle: 100 })`으로 흘려보내고 클라에서 보간합니다.
**일반 remoteFunction은 초당 ~10회 제한**이 있지만 throttled 호출은 이 제한을 우회합니다.
추가로 `NET_EPSILON` 이하로 움직이면 아예 전송하지 않아서, 가만히 있는 플레이어는 대역폭을 쓰지 않습니다.

### 2. 라운드 타이머는 월클럭

틱 간격이 변동하므로 델타를 누적하면 드리프트가 납니다. `phaseEndsAt`(서버 ms 절대시각)을
기준으로 하고, 매 틱 `tickAt`을 실어 보내 클라이언트가 시계 오프셋을 보정합니다.

### 3. 태그는 틱이 아니라 remote function

틱에서 판정하면 최대 1초가 밀립니다. `requestTag`는 즉시 실행되고, 거리·시야각·쿨다운·역할을
**서버가 전부 검증**합니다.

### 4. 페인팅: 플레이어 1명당 텍스처 1장

몸통 6개 파츠(머리/몸통/양팔/양다리)를 **하나의 512×512 텍스처에 3×2 격자로 UV 패킹**합니다.
플레이어 한 명이 텍스처 1장 + 머티리얼 1개라, 8명이어도 텍스처 8장입니다.
파츠마다 텍스처를 두면 48장이 됩니다.

붓질은 레이캐스트 히트 → UV → Canvas2D 방사형 그라디언트. 브러시가 붓 폭의 일정 비율 이상
움직였을 때만 점을 기록하고(데시메이션), 받는 쪽에서 점 사이를 보간해 이어붙입니다.

**월드는 칠할 수 없고 자기 몸만 칠합니다.** 그래서 페인트는 순수 시각 요소이고,
서버는 스트로크를 **해석하지 않고 중계만** 합니다 — isolated-vm에서 canvas를 돌릴 수 없는
제약을 우회하는 게 아니라, 아예 서버가 알 필요가 없어집니다.

### 5. 중복 코드에 대한 가드

서버는 isolated-vm에서 돌아 `src/`를 import할 수 없습니다. 그래서 맵 생성기가
`src/game/map.ts`와 `server/src/rules.ts`에 **중복 존재**합니다.

어긋나면 플레이어는 A 맵을 돌아다니는데 서버는 B 맵 기준으로 스폰시키는, 타입체크로도
각 쪽 단위테스트로도 안 잡히는 조용한 버그가 납니다. `scripts/check-sync.ts`가 양쪽 53개 박스와
서버 스폰 판정을 대조합니다. **맵을 수정하면 반드시 돌리세요.**

## 알려진 한계 / 다음 단계

1. **3D 로비 허브 미구현** — 걸어다니는 허브, 접속자 표시, 포털 자동매칭이 다음 작업입니다.
2. **이동이 서버 검증되지 않습니다** — 클라이언트 위치를 그대로 믿습니다. 스피드핵/텔레포트 가능.
   프레임당 이동거리 상한 검증을 넣으면 대부분 막힙니다.
3. **페인트 중간 참여 미지원** — 라운드는 대기 상태에서만 입장 가능하므로 현재는 문제가 없지만,
   중간 참여를 허용하려면 스트로크 히스토리를 룸 컬렉션에 쌓아 재생해야 합니다.
4. `$roomTick` 실제 주기 미측정 — 배포 후 실측해서 `NET_THROTTLE_MS` 조정 필요
5. 사운드 없음 / 모바일 미지원 / VXShop·Ads 미연동

(서버 사본은 `server/src/rules.ts`). 바꿔볼 만한 것:

- `TAG.maxDistance` / `minFacingDot` — 태그가 너무 관대한지 빡빡한지
- `BRUSH.default` / `PAINT_FLUSH_MS` — 붓 감각과 동기화 지연
- `Humanoid.tsx`의 `POSE_TARGETS` — 자세별 실루엣
